Attachment triage for {{ request_id }}, prepared {{ prepared }}.

Nothing in this folder is for release, and these volumes are not for redaction. This run is for deciding which attachments to produce. Once you send your decisions back, a production run makes new volumes with the attachments you chose, and those are the ones to redact.

What is in this folder

  • {{ counts.volumes }} triage volume{{ "" if counts.volumes == 1 else "s" }} ({% for v in volumes %}{{ v.name }}.pdf{% if not loop.last %}, {% endif %}{% endfor %}). Every message, in order, with an index at the front of {{ first_volume }}. Where a message had an attachment, a one-page note names the file it was saved as, such as A0001. The pages are not numbered.
  • {{ natives_dir }}: {{ files | thousands }} file{{ "" if files == 1 else "s" }} ({{ total_size }}), each attachment once, exactly as it was sent. Each name starts with the file’s ID. They are not redacted.
  • {{ index_name }}: one row for each file, to open in Excel and fill in.
  • {{ manifest_name }}: a technical record of this run.

What to do

  1. Open the index in Excel. Each row is one file: its ID, its name, its type and size, how many messages carried it, and the date, sender and subject of the first of them. Sort and filter it as you like.
  2. Look at what you need to. Open a file from the folder by its ID, or read the message it came with in the triage volumes.
  3. Mark what is not to be produced. Type omit in the decision column and your reason in the note column. The note is printed, exactly as you write it, on the page where the attachment was and in the list of exceptions at the front of the production, so write it as you want a requester to read it. Leave the decision blank for everything to be produced. For a report sent again and again, latest produces only the most recent copy.
  4. Save and send it back. Save the index as a CSV file and send it back to whoever prepared this folder. Deleting or renaming files in the folder changes nothing: only the index does.
